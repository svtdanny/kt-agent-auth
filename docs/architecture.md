# Architecture

The current dedicated bundle and communications are described in the [README](../README.md). The [Mermaid source](architecture-current.mmd) is editable.

The [no-patch architecture](no-patch/README.md) has separate diagrams for [shared-gateway scaling](no-patch/architecture-scaling.svg), [credential management and SQL tables](no-patch/architecture-credentials.svg), and [token refresh](no-patch/refresh-protocol.svg). It shows direct per-atespace `ext_proc` routing from one shared native Envoy to namespace-local authorizers, with independent proposed HPAs. The directory includes PDF/PNG exports and distinguishes the verified routing experiment from deployment changes still to implement.

The first view now has an MVP implementation: two egress replicas, rolling updates, CPU-based HPAs for egress and the WorkerPool, and encrypted shared authentication state in PostgreSQL. Automatic scale-down is disabled. Worker demand/backlog metrics, Redis and the separate-authorizer view remain design options. PostgreSQL also stores immutable Session bindings. Platform databases, snapshots and certificate infrastructure have separate capacity and availability requirements. Run [test_scaling.py](../scripts/test_scaling.py) for the small live check and [test_postgres.py](../scripts/test_postgres.py) for concurrency/encryption/refresh tests with the race detector.

The vector layout is generated by [render_scaling_diagrams.py](../scripts/render_scaling_diagrams.py); run `python3 scripts/render_scaling_diagrams.py` for SVG, or add `--exports` with CairoSVG installed for PNG and cropped PDF. Exports contain only the diagram, without page headers or footer notes. The Mermaid files provide equivalent topology for Markdown renderers.

Each authorizer serves one project namespace containing multiple Agents. The project has one reusable WorkerPool and one dedicated proxy bundle. Native Actor transport and HTTP policy checks both apply. `ext_proc` receives request metadata over gRPC; response decisions and header mutations return to Envoy, which forwards the application request.

Source credentials and a separate project encryption key are delivered through mounted Kubernetes Secrets populated by GitLab/Vault. Only authorizer mounts them. OAuth acquisition stays in the credential resolver; [pkg/authstate](../pkg/authstate/cache.go) owns encryption, SQL persistence and refresh leases. On token use, peers recheck shared state if their last successful SQL check was at least one second ago. Idle token entries do not poll. The local test substitutes a generated mounted key for Vault delivery; it does not test Vault/GitLab integration.

The credential view shows the implemented table columns, types, nullability, primary keys and binding cleanup index. [Reference DDL](architecture-credentials-schema.sql) also includes defaults; its sources are [store migrations](../internal/store/store.go) and [auth-state initialization](../pkg/authstate/cache.go). The Session ID inside `launches.binding` is JSON data, with no SQL foreign key to `bindings`. Each project's role owns its own database; project replicas reuse that role and the same encryption key. The opaque token record ID is an HMAC over project scope, credential reference and credential configuration. Source-credential changes select a different record; the encryption key is loaded at startup and has no automatic rotation in this MVP.

The refresh sequence shows competing replicas, a 12-second conditional SQL lease, an 8-second OAuth call outside SQL transactions, and version/owner checks before publication. The stored expiry is a safe reuse deadline: token lifetime minus a refresh margin of `min(TTL / 10, 30 s)`. Other replicas poll at 100 ms while waiting for acquisition. For a valid local token, a request triggers a SQL recheck only if the previous check was at least one second ago; there is no idle token polling. Explicit invalidation clears shared state and increments its version. Failed acquisition imposes a shared two-second cooldown. Leases fence publication, but cannot make an external login exactly once after a crash. Kubernetes projects source-credential updates eventually, so changes can reach replicas at different times. Provider-triggered 401 recovery and replay remain outside the MVP.

Render this view with `python3 scripts/render_credentials_diagram.py`; add `--exports` with CairoSVG available to write PNG and PDF too. It has no page title, revision stamp or footer.

The one-second rule applies only to token-state reads. The current authorization path separately reads `auth_bridge.bindings` twice per successful credentialed request, to resolve identity and recheck revocation after credential resolution. Connection-pool size limits concurrency; it does not multiply the token recheck schedule.

An additional [shared Envoy MVP](../scripts/test_shared_egress.py) uses an unpatched Substrate API and no dispatcher. [Hardcoded project routes](../scripts/shared_egress.py) match trusted Actor filter state and apply per-route `ExtProcPerRoute.grpc_service` overrides pointing to the namespace's authorizer Service. Native destination routing remains intact. The project deployments are reused as authorizer backends; the experiment does not forward application HTTP through their Envoys or replace the dedicated deployment shown above. The live test restores the prior runtime after finishing; see [its report](../artifacts/shared-egress-mvp.json).
